Update: five of the six blocked levels were recovered

This audit judged EV3 Levels 1 and 2, Flutter Levels 1 and 2 and Python Levels 3 and 4 blocked because none of them has a per-session outline document. They do have complete slide decks, and reading those decks directly turned out to be enough: all 58 sessions are now written up and loaded, with content, projects, tasks, STEM topics, deck links and parent copy. Cybersecurity remains genuinely blocked — a single outline document and no material behind it.

The short version

The material is in better shape than the file count suggests. Twenty-one level outline documents carry the real curriculum — per-session key concepts, tasks, STEAM video links and Kahoot quizzes. Those are the source for everything below; the 700-odd slide decks are the delivery of that curriculum, not the definition of it.

Four levels can't be described session-by-session yet, because their outlines are topic lists rather than session plans. Everything else is ready to turn into structured course data. The one thing that genuinely blocks the feature is on your side, not in the Drive: there is nowhere in the API to store a session's syllabus.

Findings

Ordered by what stops work. "Blocking" means a level cannot be described to a parent at all until someone writes the missing material.

Blocking

Cybersecurity has no course material

The topic folder holds a single Cybersecurity Course Outline.docx and nothing else — no levels, no sessions, no slides. It cannot be listed as a course until somebody builds it.

Blocking

EV3 Levels 1 and 2 have no session plans

Both "outlines" are bare topic lists of about 155 characters — "What are Robotics", "What's motor", "Sensors". The Sessions(PDF) folders contain one file each where the course report describes eight sessions. There is no per-session content to summarise.

Blocking

Python Levels 3 and 4 are concept lists, not session plans

Level 3 lists GUI topics and reference links; Level 4 lists algorithm concepts and says only "between two and five problems" per session. The course report calls Level 3 "Overview-Based", so this looks deliberate — but it means neither level can produce the per-session breakdown the other levels can.

Fix

Five "new" levels would lose their outline if the old folder is deleted

You asked me to prefer the folder marked "new" on a conflict. For Arduino Level 1, Arduino Level 2, Programming Basics Level 1, Programming Basics Level 2 and Python Level 3, the outline document lives only in the old folder — the new one has the session files but no curriculum document. Copy the outlines across before archiving anything.

Fix

Web Development Level 1 is missing a session file

The outline describes 12 sessions; Session(PDF) contains 11. Worth finding which one before the level is published.

Fix

An internal work note is sitting in a course folder

Arduino/Level 2 new/Arduino level 2.docx is not curriculum — it is a task assignment listing three staff members by name against session ranges, with a deadline of 22/8. It reads as course material to anyone browsing the folder, and it names staff. Move it out.

Fix

WeDo and EV3 session folders hold one file where eight are expected

All four Sessions(PDF) folders under WeDo and EV3 contain a single item, though eight session decks sit loose in the level folder above. Either the PDFs were never exported or they live somewhere else. WeDo at least has proper per-session outlines, so its content is recoverable; EV3's is not.

Fix

Flutter Level 2's outline will not download

Flutter Course Outline Level 2.docx returns zero bytes while Level 1's returns 991 KB — likely a per-file sharing setting. Flutter also has no per-level outlines and no session subfolders, and its Development folder holds sessions 5 to 11 in a way that looks like work in progress.

Tidy

Session files are named after their download history

Files are called 5 (1) (1).pptx, 8 (3).pptx, 2 .pptx — a number plus browser duplicate-suffixes, sometimes with a trailing space. Nothing carries a title. If the LMS is going to link to these, rename them to something stable like PY-L1-S05.pdf first, or the links will break the next time someone re-uploads a file.

Tidy

Four different names for the same folder

Sessions(PDF), Session(PDF), Sessions slides and Session slides all mean the same thing; levels are numbered Level 1 in nine topics but Level One and Level two in AI; and the duplicates are marked (NEW), new, NEW and (New). Any script that imports this has to special-case all of it.

Tidy

Two course reports describe things that aren't there

The Programming Basics report describes four levels; the Drive has three. The Python report says "32+ sessions" where the levels actually total 38. Parents and instructors read these reports, so they're worth correcting.

Tidy

App Inventor Level 1 is missing three project files

The Projects folder covers sessions 1–5 and 7–10. Sessions 6, 11 and 12 have slides but no project document.

Getting this into the system

There's nowhere to put it yet

The API models Topic → CourseLevel, and a level carries only title, description and sessionCount. Scheduled sessions carry a free-text topic string. Nothing holds a syllabus.

A per-session table is needed — course level, session number, title, key concepts, task, parent summary, material link. I can deliver every level as JSON keyed to your existing topic and level IDs so it seeds in one pass, and build the screens against it, but the endpoint has to exist first.

Parents have no way to log in

Role is Student, Instructor and Admin. If parents are going to receive these summaries, the realistic options are a printable per-session sheet, a per-term PDF, or surfacing it on the student's own account. The certificate generator already produces PDFs from templates, and the same approach would cover a session sheet without new dependencies.

Four topics have no topic code

resolveTopicCode() explicitly maps Python, Arduino, WeDo, AI, Programming Basics and Mobile App Development. Cybersecurity, EV3, Flutter and Web Development fall through to the initials fallback, which happens to produce sensible codes (CY, EV, FL, WD) but only by luck. Worth adding them explicitly before these codes end up printed on certificates.
